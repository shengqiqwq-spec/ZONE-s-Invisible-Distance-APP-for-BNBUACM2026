6常见改动怎么做

6.1 改文案（最常见）

  • 改路线对比表 / 条形图数字 → 找 var VIEWS（约 1131 行）。每个视角一个对象， 里面的 rows 是表格内容，dist/time/floorBar 是条形图数值。 只改一个视角会造成三个视角口径不一致，记得三个都改。
  • 改某个视角的推荐结论 → 同一个对象里的 badgeText（徽章）、note（解释段落）、 rec（'A' 或 'B'，决定表格里哪个单元格标绿）。
  • 改楼层提示文案 → var FLOOR_DATA（约 1001 行），每个 key 对应下拉框里的一个选项。
  • 改页脚 / 副标题 / 数据来源说明 → 直接搜中文原文。数据来源那段（含分级表）在约 887 行。

6.2 加一个新的楼层选项

  1. 在 <select id="floorSelect"> 对应的 <optgroup> 里加一个 <option value="xxx-N">。
  2. 在 FLOOR_DATA 里加一个同名 key，填 title / status / statusText / desc / routeNote。
注意 value 的命名规则：必须以 lib- 或 v27- 开头（或其他已存在的楼栋前缀）， 因为 renderFloor() 靠前缀来判断要不要在地图上高亮对应楼栋。而高亮又要求那栋楼有 id="bld-xxx"。要新增一栋可高亮的楼，得同时补 id。

6.3 加一条全新的路线对

目前作品只支持「图书馆 → V27」这一对。扩展需要改三处，工作量不小：

  1. 画路线：在 SVG 的路线图层里加 <path class="lyr-route route-A"> 之类的路径，坐标要落在步道上。参照现有路线 A/B 的写法。
  2. 加数据：在 VIEWS 里为每个视角补上这条新路线的距离/时间/高差。
  3. 加交互：如果新路线对需要自己的视角切换，那就要再扩 VIEWS 的结构和 setView()，改动会扩散到 UI。

建议：先把「路线对」做成数据驱动（一个数组 + 一个渲染函数），比直接复制粘贴三套更省事。但目前没做，改之前想清楚。

6.4 改配色 / 视觉

  • 整体色板 → 文件顶部 :root 里的 CSS 变量（约 9–35 行）。优先改变量，不要到处改硬编码颜色。
  • 建筑颜色 → 搜 .b-teach（教学楼）/ .b-dorm（宿舍）/ .b-fac（大型设施）。同时记得改图例里的色块。
  • 路线颜色与强调逻辑 → 搜 .route-A / .route-B（约 291–298 行）。 .view-walker / .view-luggage / .view-wheelchair 三组规则决定「当前视角下哪条路线被加粗」。
  • 数据来源区块的表格样式 → 搜 .grade。

8红线与坑

8.1 代码红线（改了就会坏）

  1. 禁止再用 setAttribute('class', ...) 整体写 SVG 的 class。 SVG 上的 class 同时承载四个状态：view-*（视角）、routes-visible（路线开关）、 mode-access（无障碍视角）、floor-active（楼层高亮）。 任何新状态都必须加进 svgState 和 applySvgClass()，让它统一拼装。 （脚本里的「class 只在 applySvgClass 里写一次」这条断言就是守这个的）
  2. 不要在 wheel 处理器里无条件 preventDefault()。 地图占了页面大部分区域，无条件吞掉滚轮会让用户再也滚不动页面。缩放必须要求 ⌘/Ctrl。
  3. 不要给 SVG 恢复 touch-action: pan-x pan-y pinch-zoom。 它会让浏览器原生手势和 JS 手势同时生效，结果是抖动和双重缩放。现在是 touch-action: none，别动。
  4. 不要试图用纯 transform 缩放却不做平移夹取。 transform 不改变布局尺寸，没有夹取的话放大后地图会飞出可视区域。夹取逻辑在 apply() 里。
  5. 不要删数据来源区块里的「数据真实性分级表」和「模拟数据声明」。这是赛题的硬性要求，删了等于送分给对手。

8.2 数据红线（改了就是错的）

  1. 图书馆是 4 层，出入口在 2F 朝东南，无台阶。OSM 标 1 层是错的。别再引用 OSM 的楼层数覆盖它。
  2. 图书馆 → V27 是 −1 层（下坡），不是上坡。方向反了的话，整个「普通行人推荐台阶近路」的论证都不成立。
  3. 不要把中心湖画成实心精确湖面。现有湖岸线多边形经过几何自检，压住了 16 条真实 OSM 步道和 6 段台阶， 形状本身就不准——原作者当年发现穿模后，是用背景色把它涂掉来回避的（这就是「地图上找不到中心湖」的真正原因）。 当前岸线为卫星图目测描绘版（以 T4 教学楼/文化创意群落/演艺厅锚点对齐）；若后续拿到 GPS 轨迹或 OSM 补录水域，再做更高精度替换。不要回退到旧的手绘示意多边形（它压住 16 条步道，位置也偏）。 （脚本里有「湖岸线为实心卫星图描绘版」断言守着，d 以 668 398 开头）
  4. 中心岛的坐标不要挪回原来的位置（约 M 555 440 …）。那个位置落在图书馆轮廓内部， 会被后绘制的建筑完全盖住——这个元素从做出来那天起就没被显示过。现在它在 M 724 468 …。
  5. 除图书馆和 V27 外，其余楼栋的楼层数来自 OSM 社区标注，未经核实。引用时要说明这一点，别当成事实宣讲。
  6. 路线长度已实测（2026-10-12）：A 537 m、B 470 m。提交材料与作品页均需保持实测口径；尚未实测：轮椅/行李耗时、室内路线 C。
